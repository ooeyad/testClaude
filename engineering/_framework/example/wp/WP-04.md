# WP-04 — ASM-001 constructor hook

**Status:** todo · **Depends:** — · **Refs:** AD-002, BD-001, INV-4, STD-04, STD-21

## Contract

**Goal.** Let an enemy definition supply its own constructor, so a later package
can register a `Climber` — without changing what happens for any definition that
does not supply one.

**Done when.**
1. `Enemy.spawn` constructs `cfg.ctor` when the definition provides one, and
   `P.Enemy` when it does not.
2. With no definition supplying `ctor` — which is the state of the tree after
   this package — the game's behaviour is byte-for-byte unchanged in effect: the
   four existing types still construct `P.Enemy`.
3. `node --check` passes for every script in `index.html` load order.
4. The game boots and plays with no new console error.
5. `git diff --stat` shows exactly one file changed.

**Touches.** `phefo/js/entities/enemy.js` — **only** the `spawn` function.

**Forbidden.**
- Every other file. In particular do not create `entities/climber.js` or touch
  `entities/enemies/*.js` — those are WP-06.
- Within `enemy.js`: the state machine (`idle/chase/telegraph/attack/recover`),
  `update`, `walk`, `separate`, `runAttack`, `pose`, `draw`, and the 120 px
  targeting gate. This package changes construction, nothing else.

**Must not change.**
- The behaviour of knifeman, swordsman, gunman and archer — proven structurally:
  none of them defines `ctor`, so the fallback branch is the only one taken.
- INV-7's targeting gate. It stays exactly as it is; the climber will bypass it
  with its own elevation model in WP-07, not by editing this file.

## Notes
- This is **the only approved shared modification in the entire opportunity**
  (ASM-001). Everything else in the design is a new file, a new key, or new
  data. Treat any temptation to "also just fix" something in this file as a
  scope breach — record it as `TD-nnn` and move on.
- The fallback must be a plain `cfg.ctor || P.Enemy`. Do not add a registry, a
  factory or a type switch; the whole value of AD-002 is that the change is
  inert and readable in one line.
- `P.Enemy` is referenced at call time here, not captured at IIFE time, so this
  does not add a load-order constraint (INV-4). Keep it that way.
- ES5 only — `var`, no arrow functions, no default parameters (STD-21).
- Constructing through a variable changes nothing about how the resulting object
  is used: the rest of `spawn` must operate on the instance exactly as before.
